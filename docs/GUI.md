# GUI 显示与日志

启动方式保持不变：项目根目录执行 `python -m dapremote gui`，或在 PyCharm 以模块 `dapremote`、参数 `gui` 运行。连接本地模拟器前先启动 `python -m dapremote sim --root sim_sd`。

## 界面

- 统一浅色背景、蓝色主要操作、清晰的页签与表头；删除和取消使用红色操作样式。
- 顶部显示连接状态、设备、电量、电压和 SD 状态，不直接展示协议会话编号。
- 文件大小使用 B / KiB / MiB；文件校验摘要缩短显示，完整数据仍由底层 API 保留。
- 上传和取回显示进度；烧录任务分开显示阶段、已写入字节数与校验结果。
- 烧录页采用可拖动分隔条的左右分栏：左侧 HEX 原文预览，右侧保留烧录控制、阶段、进度与任务日志。
- 烧录页不显示内部编号。选择 HEX 与 FLM 后点击“开始烧录”，任务结束后再次点击即可启动新一轮；执行期间按钮禁用，防止误点。
- 测速失败的行标红，未通过的数据不当作有效吞吐展示；没有通过档位显示中文提示，不显示 None。

## 操作日志

GUI 不再把响应字典或 JSON 直接写入日志。日志采用如下形式：

```text
14:23:10  SUCCESS  连接成功 · DAP-SIM-001
14:23:12  INFO     已读取目录 / · 3 项
14:23:18  SUCCESS  上传完成 · app.hex → /HEX/app.hex · 32.0 KiB · 文件校验通过
14:23:25  ERROR    上传失败：SD 卡可用空间不足，请清理文件后再试。
```

| 级别 | 颜色 | 场景 |
|---|---|---|
| INFO | 灰蓝 | 状态与操作记录 |
| SUCCESS | 绿色 | 连接、传输、校验成功 |
| WARN | 橙色 | 主动取消、断开连接、实时缓存丢失 |
| ERROR | 红色 | 请求失败、任务失败、测速校验不一致、SD 输出异常 |

日志为只读，可选择复制，也可用“复制”按钮复制全部保留记录；“清空”只清理界面，不删除设备数据。自动滚动可关闭，便于检查历史。保留行数有上限，长时间采集不会无限累积界面文本。

“错误弹窗”默认开启：用户操作失败时显示说明和处理建议，同时记录红色 ERROR。关闭该选项后仍记录错误，不会静默忽略。

后台 RTT / 任务刷新失败仅记录错误并暂停刷新，不反复弹窗；用户可检查连接后重新连接。SD RTT 输出异常、测速中某一候选档位失败也会写红色日志，避免每个轮次都弹窗；整个测速或任务失败时才提示一次。

任务轮询仍然更新进度，但只有阶段或终态变化才新增日志，避免同一任务反复刷屏。主动停止测试属于提醒，不作为系统错误弹窗。

## RTT 文本

RTT 窗口默认显示 UTF-8 文本，保持跨数据块的字符解码。换行直接显示；00、FF 等无法作为正常文本展示的字节以 `\x00`、`\xff` 显示，不显示 Python 的 `b'...'` 或 JSON 转义字符串。SD 保存的数据没有被此显示格式转换。

## 一键烧录与内部操作编号

正常使用只需要通过弹窗选择 HEX 和 FLM，并点击“开始烧录”。无需先点击“检查 HEX”：设备接受烧录任务前仍会检查文件。也无需生成、输入或保存查询码。

每个明确的新烧录意图自动生成一个随机操作编号。它的作用是区分“用户再次要求烧录”与“同一次请求因为通信异常被重发”。例如设备已开始擦除但回复丢失，电脑无法单靠超时知道是否执行；沿用原编号可以查询原任务，避免重新擦除和烧录。

- 新的用户操作：自动使用新编号，因此同一 HEX 可以连续多次烧录。
- 同一次通信重试：使用原编号；同编号同参数返回原任务，同编号不同参数被拒绝。
- 回复丢失、断线或 GUI 重启：重新连接后自动用已有记录查询任务；状态无法确认时不盲目创建新任务。
- “刷新任务状态”只查询当前设备的最近一次烧录，不启动新烧录，不需要填写编号。

编号不是文件校验码，也不是设备认证密码。CRC/SHA-256 用来检查数据是否一致；操作编号用来识别业务是否为同一次执行。

本地恢复记录保存在项目 `.dapremote/gui-flash.json`，已被 Git 忽略。程序在向设备发送烧录指令之前保存编号、固件版本与目标信息；后台任务查询更新状态。记录按连接地址和设备标识区分，每个设备保留最近一次，最多 128 个设备。GUI 与日志均不显示编号。记录损坏或无法在发送前保存时停止新烧录并提示，不静默删除恢复证据。

断线并不证明烧录失败。如果设备任务记录已丢失，GUI 会明确报告结果不确定，不能凭空承诺只执行一次。当前不提供用于跳过此判断的自动重放；应检查设备结果及恢复记录后处理。真实设备应提供稳定且唯一的 device_id。

Python 客户端和 CLI 仍保留显式 operation_token 参数，供脚本精确控制；GUI 使用 `dapremote/gui_flash.py` 的 `FlashCoordinator` 自动管理。

| 接口 | 说明 |
|---|---|
| `FlashCoordinator(state_path=None)` | 加载可选本地恢复记录；不传路径只保留内存状态 |
| `start(client, endpoint, path)` | 新操作自动编号并提交；前次未确认则仅查询；返回 `job,recovered` |
| `query(client, endpoint)` | 查询已有操作，不发送 FLASH_START；无已提交操作时返回 None |
| `observe(client, endpoint, job, persist=True)` | 更新本地任务状态，GUI 后台执行持久化 |

控制器方法可能抛出 `PendingFlashError`，表示恢复记录或上次执行结果不确定；GUI 将其转换为可读错误提示。GUI 关闭不会取消已接受的设备任务。

## HEX / FLM 文件选择与固定目录

主界面不提供手填固件路径。点击“选择 HEX…”打开资源管理器弹窗，左侧切换“设备 SD 卡”和“此电脑”及本地磁盘，右侧浏览 HEX 文件及文件夹。弹窗默认尺寸按屏幕调整；底部选择和取消按钮保留固定空间，仅文件列表随窗口缩放。长文件名和位置不会把底部按钮挤出窗口。

FLM 不再打开文件选择弹窗。烧录页使用只读下拉框，连接后自动加载 SD `/FLM` 目录的 `.flm` 文件名（不递归子目录，不显示其他类型），可点“刷新 FLM”重新读取。用户明确选择算法后才启用烧录。为空时提示在文件管理中上传 FLM；先在文件管理中双击进入 `/FLM` 再上传，文件管理不会自动改变目标目录。刷新保留版本未变的选择；所选文件被删除或变化时清除选择，要求重新选择。断开连接会清空算法列表和选择。

| 类型 | SD 固定目录 | 可见文件 |
|---|---|---|
| HEX 固件 | `/HEX` | 该目录及其子目录中的 `.hex`，大小写不敏感 |
| FLM 烧录算法 | `/FLM` | 仅该目录直接包含的 `.flm`，大小写不敏感 |

目录由程序按需创建；若被同名文件占用则报错。HEX 的 SD 浏览不能退到 HEX 文件库以外。电脑可浏览本地文件夹和磁盘，但只显示 HEX 文件及文件夹。选择电脑文件后立即保存副本、上传、核对完整性；成功后才替换当前选用项，随后 HEX 自动加载预览。失败或取消选择时保留原选择。取消正在进行的上传弹窗不会撤销已发送的数据，已完成的文件可能留在 SD，但不会自动烧录。

首次上传保留原文件名（文件名主体最多 60 字符），同名同内容直接复用；同名不同内容时才弹窗询问是否覆盖，默认选择“不覆盖”。拒绝时取消此次上传并保留原文件与当前选择。HEX 选择弹窗中的本地导入保存到 `/HEX`；文件管理中的上传始终保存到当前目录，所有文件类型一视同仁。电脑副本和按设备/boot 隔离的续传记录保存在 `.dapremote/firmware-cache/`，不写入源文件目录。同一设备同一次开机内可重试续传，设备重启则重新上传。上传和烧录是两个明确动作：选文件只上传，点击“开始烧录”才烧录。

HEX 和 FLM 均选定后才启用烧录按钮。烧录前检查 HEX 内容、所选 FLM 版本、目标信息；请求携带两个文件各自的 SHA-256。任务运行期间设备同时锁定 HEX 和 FLM，删除或替换会被拒绝。文件管理中的 HEX、FLM 和普通文件都上传到当前浏览目录，不做类型归档；若希望用于烧录选择，应先进入相应文件库再上传。文件管理列表支持双击文件夹进入；双击普通文件不执行打开、预览、跳转烧录页或选用算法等操作。文件可单击选择后通过工具栏按钮处理，也可通过顶部目录栏指定目录后刷新。已有散放文件不会自动移动，可重新从电脑上传或通过文件 API 整理。

**模拟器边界：**FLM 是芯片烧录算法，不是普通固件。当前模拟器只验证 ELF32、小端、ARM 基本文件头和版本，仍使用内置的模拟目标执行擦写；不执行上传的 FLM，也不验证其符号、FlashDevice、RAM 布局或与真实芯片的适配。真实 DAP 固件必须完成 FLM 加载和算法函数调用，详见 [CMSIS-Pack Flash Programming](https://open-cmsis-pack.github.io/Open-CMSIS-Pack-Spec/main/html/flashAlgorithm.html)。测试的 ELF 头样本仅用于协议测试，不能用于芯片烧录。

## HEX 预览

保留左右分栏：左侧只读 HEX 原文、行号与记录着色，右侧为 HEX 弹窗选择、FLM 算法下拉框、烧录状态和任务日志。选择 HEX 后自动预览，也可刷新；更换文件立即清除旧内容，旧请求不能覆盖新文件。蓝色为扩展地址、绿色为 EOF、紫色为起始地址、红色为记录格式或校验异常。

默认读取前 16 KiB，加载更多每次加倍，最高 256 KiB、最多 4000 行。被截断的尾记录用橙色显示，不误报校验失败。整份读取时核对 SHA-256，前缀读取只标注已显示/总大小。预览不代替烧录前设备检查；FLM 为二进制文件，不放进 HEX 文本预览。

## 开发接口

界面格式化放在 `dapremote/gui_text.py`，与二进制协议和业务客户端分离：

| 接口 | 用途 |
|---|---|
| `result_notice(value) -> Notice` | 将已知业务结果转换成简短文字和级别；不序列化整个字典 |
| `error_notice(exception) -> Notice` | 将设备状态码与连接错误转换成可读说明 |
| `job_notice(job) -> Notice` | 任务阶段与终态说明 |
| `scan_notice(summary) -> Notice` | 测速扫描汇总，含模拟与恢复失败说明 |
| `RttTextDecoder.feed(data, final=False) -> str` | 有状态 UTF-8 解码与二进制显示转义 |

`Notice` 包含 `text` 和 `level`。GUI 的 `report_error` 统一负责红色记录和可选弹窗；UI 控件仅在主线程更新。日志排版不改变设备返回的原始字段，也不改变 CLI 为脚本提供的 JSON 输出。

验证：`python -m unittest discover -v` 检查文案、级别、二进制文本与原协议回归；桌面环境下 `python scripts/gui_smoke.py` 用隐藏窗口检查真实控件、连接、测速、红色 ERROR、弹窗选项、任务日志去重与 RTT 文本。


文件管理上传不再询问设备目标路径：所有文件都使用当前目录及原文件名，双击进入哪个文件夹就上传到哪个文件夹；上传后保留当前目录。无重名时直接上传，不弹出覆盖询问。目标名称被文件夹占用时提示错误，不尝试覆盖目录。文件管理上传与 HEX 弹窗中的本地上传采用相同的冲突询问规则。新建目录仍保留名称/路径输入框。


烧录算法仅允许 `.FLM`（大小写不敏感）。FLX 不在算法下拉框中显示，客户端与模拟器也拒绝将 FLX 作为烧录算法。文件管理仍可将任意类型文件作为普通文件存储，不意味着该文件可用于烧录。
